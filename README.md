# fish-eye

> **不再维护（not maintained）**
> 这是从一个私人项目里抽出来的东西：两个跑通过、踩过坑的脚本，加上一路上量出来的数字。留在这里是给人参考的，issue 和 PR 不一定回。

让模型**陪你一起看**视频：不下载、不截屏，连上你已经打开的那个浏览器，在播放器页面里按画面变化抓帧，拼成宫格交出来。B站是第一个适配器。

它和"把视频丢进去做一次性分析"是两件事：那个是看完给结论，这个是**随着播放一段段往下看**——看到第几分钟、画面里发生了什么、这一段的台词是什么。陪着看和总结，用起来差很远。

## 核心做法

1. **本地高频扫描**：页面里每 0.5 秒取一张 32×18 的缩略图，和上一张算平均绝对差，在浏览器里打分，不花模型的钱。
2. **按变化留帧**：差异够大（换镜头、动作戏）才从 `<video>` 上 drawImage 一张 640×360 的格子；画面没动就跳过，但每 20 秒强制留一张兜底。
3. **凑满就交**：攒满 4 格（2×2）立刻 `toDataURL` 交回 node 落盘——不在页面里攒，因为分段导航会把页面清了。
4. **一段一交**：跑满 5 分钟、攒满 12 张或播完就收尾，返回每张图的位置和每格的秒数，调用方再配上这段时间的字幕。

## 为什么不是"1 秒一帧"

这是整个项目里最值钱的部分：三个数字，两次改法。

**① 变化阈值 12 → 20。** 实测换镜头时相邻两帧的亮度平均绝对差是 160~220，静止画面是 0.16——差 1000 倍。阈值 12 太敏感，"有辆车开过去"都算换镜头；20 只抓真切换。

**② 兜底间隔 5 秒 → 20 秒。** 这一步收益最大：同样 5 分钟，兜底触发从 13 次降到 1 次，同样的张数能覆盖一倍的时间。静止画面的兜底还要再拉长 3 倍（画面标准差 < 0.3 时），否则那种 30 秒定格会刷屏。

**③ 1920×1080 → 1280×720。** B站 的源常常只有 852×480，输出 1080p 只是把 480p 放大，token 却按 1080p 算。这一改省 53%，画质一点没少。

### 顺带量出来的 token 账

模型按像素网格算图，**和文件大小无关**（DeepSeek 是 42px 一格，`tokens = rows × (cols+1) + 2`）：

| 整图尺寸 | 每张 token | 4 格时每格 |
|---|---|---|
| 1920×1080 | 1224 | 960×540 |
| **1280×720** | **578** | **640×360** |
| 1024×576 | 366 | 512×288 |

而更反直觉的是这条：**一轮 20 次工具调用大约 ¥0.46，其中图片 token 只占 2,890——不到千分之一。** 钱全在"每调一次工具，整个十几万字的上下文重放一遍"。

所以**省钱的唯一办法是减少调用次数，不是减图。** 这也是为什么一批要一口气给 5 分钟，而不是几十秒一叫。

## 装成 DSH 插件（调参数用）

这个仓库本身就是一个 DSH bundle：装进 DSH 之后，**设置 → 陪看**里多一个分区，四根滑块调抓帧节奏。

装法二选一：

- **界面**：DSH 侧边栏 → 插件 → Add plugin → 选这个目录
- **命令**：`plugin_manager` 动作 `install_bundle`，target 填这个目录的绝对路径

装完在 设置 → 陪看 里调；拖动即存，写进：

```
~/.dsh/see-now/watch-tuning.json
```

抓帧脚本启动时读这个文件当默认值（`--th` / `--scan` / `--force-gap` / `--max-grids` 显式给了就用命令行的）。想换位置设 `FISH_EYE_TUNING`。

> 只调参数、不带抓帧功能本身。抓帧还是跑 `src/watch-frames.mjs`——它不依赖 DSH，单独也能用。

## 快速开始

需要：Node ≥ 22、一个开了 CDP 的 Chromium 系浏览器（守护脚本是 Windows 专用，抓帧本身跨平台）。

```bash
# 1. 用独立 profile 起浏览器，开调试端口，打开一条视频
#    （独立 profile 是为了不碰你自己的浏览器登录态）
msedge --remote-debugging-port=9333 \
       --user-data-dir=%TEMP%\bili-watch-profile \
       "https://www.bilibili.com/video/BV1xx411c7mD"

# 2. 抓 5 分钟，输出宫格图的路径和每格秒数
node src/watch-frames.mjs --seconds 300 --json

# 3.（可选）守着那个窗：置顶、被跳走拉回、播完关窗、每 14 分钟分段续播
node src/player-guard.mjs
```

抓帧脚本输出到 `~/.cache/bili-watch-frames/<BV号>/grid-<BV>-<序号>-<时间戳>.jpg`，每格左上角烧着秒数。

## 参数表

| 参数 | 默认 | 实测怎么定下来的 |
|---|---|---|
| `--scan` | 0.5 秒 | 再密没意义（动画最快也就这个量级），再疏会漏切换 |
| `--th` | 10（建议 20） | 见上：换镜头 160~220，静止 0.16，20 只抓真切换 |
| `--min-gap` | 3 秒 | 两次留帧的最短间隔，防止动作戏每 0.5 秒都留 |
| `--force-gap` | 20 秒 | 兜底。5 → 20 秒是收益最大的一次改动 |
| `--cols` × `--rows` | 2×2 | 每格 640×360，这个尺寸连"横浜市立西中学校"这种字都读得清 |
| `--max-grids` | 8（MCP 里用 12） | 传输上限决定，见下一节 |
| `--loud-spike` | 1.8 | 音量突增**只记录、不触发抓帧**：爆炸之后立刻多塞一张，等于把看片的人吓醒 |

## 交给模型时，三个坑

**① 传输有上限，超了会静默丢图。**
一段 19~22 张 1280×720 JPEG，base64 之后约 7MB，超过 MCP 单条消息的上限，图片被丢掉而 `ok` 还是 `true`——你在上层完全看不出问题。压到 12 张、JPEG quality 0.85，约 3MB 就安全了。**这个值要按你的宿主上限重新定，不是通用常量。**

**② B站 的字幕轨可能是错的。**
我们遇到过一条：动画片挂了 428 条 AI 字幕，内容是英雄联盟解说（"恭喜BLG""他们要去伦敦了"），跨度 765 秒、而片长 6969 秒。`src/subtitle-guard.js` 就是为这个写的，三个判据：

- **覆盖率**：字幕跨度不到片长的 30% → 丢。**只有这一条真挡得住错轨**（那条片子 11%）。
- **密度**：平均每 10 秒不到 1 条 → 丢。挡的是残轨。
- **断层**：相邻两条之间空白超过 120 秒 → 丢。也挡残轨。

顺带两条实测出来的坑：密度和断层**对上面那条错轨都是"正常"的**（5.59 条/10 秒、最大断层 25.8 秒），所以别把它们当错轨检测；断层阈值放到 30 秒会误杀真字幕（一条纪录片中间有 41 秒纯音乐没人说话）；AI 字幕的时长经常比片长还长（合集/多P，实测 136%~1486%），所以覆盖率只在"字幕跨度 < 片长"时才有意义。

**③ 字幕错了要让它知道。**
把这类话放进**工具返回的那段文本**里，别写进系统提示词——系统提示词全局生效、每轮都在付钱，而这个问题只在看片时出现：

> 字幕只是参考。画面和字幕对不上就是串台了——只按画面说，别拿字幕编剧情。

## 目录

```
src/
  watch-frames.mjs   核心：连 CDP、页面内抓帧、变化检测、拼宫格、落盘（零依赖）
  player-guard.mjs   播放窗守护：置顶、被跳走拉回、播完关窗、分段续播、播完兜底（Windows）
  subtitle-guard.js  字幕轨校验：覆盖率 / 密度 / 断层，纯函数
  replay.mjs         调试：把播放页倒回某一秒
docs/
  token-cost.md      token 账的完整推算
```

环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `BILI_CDP_PORT` | 9333 | 浏览器调试端口 |
| `BILI_FRAME_DIR` | `~/.cache/bili-watch-frames` | 宫格图落盘位置 |
| `BILI_WATCH_LOG` | `<FRAME_DIR>/guard.log` | 日志 |
| `BILI_EDGE_PROFILE` | `<FRAME_DIR>/edge-profile` | 守护关窗时按这个 profile 名杀进程 |
| `BILI_REGION_FILE` | 空 | 设了才把播放器的屏幕矩形写出去（给按矩形截图的工具有个准框） |
| `BILI_SEGMENT_MS` | 840000 | 单段最长多久硬性停一次再续播 |
| `BILI_CLOSE_AFTER_MS` | 35000 | 播完多久关窗 |
| `BILI_CLOSE_AFTER_PAUSED_MS` | 600000 | 一直暂停多久关窗 |

## 已知问题（没打算修）

1. **固定机位的长镜头会被误判成换镜头**：路过一辆车就算切换，拼出来 4 格几乎一样。治法是阈值提到 28 以上，或者只看画面中心区域。
2. **每批覆盖不全 5 分钟**：撞上 `max-grids` 上限就先交（实测 12 张约覆盖 195 秒）。想看满 5 分钟得把上限提上去，又会撞传输上限——两头夹。
3. **音量信号采到了但没用于决策**，只记在返回值里。
4. 分段续播（14 分钟）和一批 5 分钟撞在一起的情况，实测过一次能活，但样本很少。
