# fish-eye 👁️

*A clearer pair of eyes for AI companions.*

> **不再维护（not maintained）**
> 这是从一个私人项目里抽出来的东西：两个跑通过、踩过坑的脚本，加上一路上量出来的数字。留在这里是给人参考的，issue 和 PR 不一定回。

让模型**陪你一起看**视频：不下载、不截屏，连上你已经打开的那个浏览器，在播放器页面里按画面变化抓帧，拼成宫格交出来。B站是第一个适配器。

它和"把视频丢进去做一次性分析"是两件事：那个是看完给结论，这个是**随着播放一段段往下看**——看到第几分钟、画面里发生了什么、这一段的台词是什么。陪着看和总结，用起来差很远。

## 核心做法

1. **本地高频扫描**：页面里每 0.5 秒取一张 32×18 的缩略图，和上一张算平均绝对差，在浏览器里打分，不花模型的钱。
2. **按变化留帧**：差异够大（换镜头、动作戏）才从 `<video>` 上 drawImage 一张 640×360 的格子；画面没动就跳过，但每 20 秒强制留一张兜底。
3. **凑满就交**：攒满 4 格（2×2）立刻 `toDataURL` 交回 node 落盘——不在页面里攒，因为分段导航会把页面清了。
4. **一段一交**：跑满 5 分钟、攒满 12 张或播完就收尾，返回每张图的位置和每格的秒数，调用方再配上这段时间的字幕。

## 为什么不是"1 秒一帧"

这是整个项目里最值钱的部分：三个数字，两次改法。

**① 变化阈值 12 → 20。** 实测换镜头时相邻两帧的亮度平均绝对差是 160~220，静止画面是 0.16——差 1000 倍。阈值 12 太敏感，"有辆车开过去"都算换镜头；20 只抓真切换。

**② 兜底间隔 5 秒 → 20 秒。** 这一步收益最大：同样 5 分钟，兜底触发从 13 次降到 1 次，同样的张数能覆盖一倍的时间。静止画面的兜底还要再拉长 3 倍（画面标准差 < 0.3 时），否则那种 30 秒定格会刷屏。

**③ 1920×1080 → 1280×720。** B站 的源常常只有 852×480，输出 1080p 只是把 480p 放大，token 却按 1080p 算。这一改省 53%，画质一点没少。

### 顺带量出来的 token 账

模型按像素网格算图，**和文件大小无关**（DeepSeek 是 42px 一格，`tokens = rows × (cols+1) + 2`）：

| 整图尺寸 | 每张 token | 4 格时每格 |
|---|---|---|
| 1920×1080 | 1224 | 960×540 |
| **1280×720** | **578** | **640×360** |
| 1024×576 | 366 | 512×288 |

而更反直觉的是这条：**一轮 20 次工具调用大约 ¥0.46，其中图片 token 只占 2,890——不到千分之一。** 钱全在"每调一次工具，整个十几万字的上下文重放一遍"。

所以**省钱的唯一办法是减少调用次数，不是减图。** 这也是为什么一批要一口气给 5 分钟，而不是几十秒一叫。

## 装成 DSH 插件（调参数用）

这个仓库本身就是一个 DSH bundle：装进 DSH 之后，**设置 → 陪看**里多一个分区，四根滑块调抓帧节奏。

装法二选一：

- **界面**：DSH 侧边栏 → 插件 → Add plugin → 选这个目录
- **命令**：`plugin_manager` 动作 `install_bundle`，target 填这个目录的绝对路径

装完在 设置 → 陪看 里调；拖动即存，写进：

```
~/.dsh/see-now/watch-tuning.json
```

抓帧脚本启动时读这个文件当默认值（`--th` / `--scan` / `--force-gap` / `--max-grids` 显式给了就用命令行的）。想换位置设 `FISH_EYE_TUNING`。

> 只调参数、不带抓帧功能本身。抓帧还是跑 `src/watch-frames.mjs`——它不依赖 DSH，单独也能用。

## 快速开始

需要：Node ≥ 22、一个开了 CDP 的 Chromium 系浏览器（守护脚本是 Windows 专用，抓帧本身跨平台）。

```bash
# 1. 用独立 profile 起浏览器，开调试端口，打开一条视频
#    （独立 profile 是为了不碰你自己的浏览器登录态）
msedge --remote-debugging-port=9333 \
       --user-data-dir=%TEMP%\bili-watch-profile \
       "https://www.bilibili.com/video/BV1xx411c7mD"

# 2. 抓 5 分钟，输出宫格图的路径和每格秒数
node src/watch-frames.mjs --seconds 300 --json

# 3.（可选）守着那个窗：置顶、被跳走拉回、播完关窗、每 14 分钟分段续播
node src/player-guard.mjs
```

抓帧脚本输出到 `~/.cache/bili-watch-frames/<BV号>/grid-<BV>-<序号>-<时间戳>.jpg`，每格左上角烧着秒数。

## 参数表

| 参数 | 默认 | 实测怎么定下来的 |
|---|---|---|
| `--scan` | 0.5 秒 | 再密没意义（动画最快也就这个量级），再疏会漏切换 |
| `--th` | 10（建议 20） | 见上：换镜头 160~220，静止 0.16，20 只抓真切换 |
| `--min-gap` | 3 秒 | 两次留帧的最短间隔，防止动作戏每 0.5 秒都留 |
| `--force-gap` | 20 秒 | 兜底。5 → 20 秒是收益最大的一次改动 |
| `--cols` × `--rows` | 2×2 | 每格 640×360，这个尺寸连"横浜市立西中学校"这种字都读得清 |
| `--max-grids` | 8（MCP 里用 12） | 传输上限决定，见下一节 |
| `--loud-spike` | 1.8 | 音量突增**只记录、不触发抓帧**：爆炸之后立刻多塞一张，等于把看片的人吓醒 |
| `--sub-ocr` | 1（开） | 字幕条 OCR。设 0 关掉。需要先装 RapidOCR，见下 |
| `--sub-gap` | 1.5 秒 | 隔多久看一眼画面底部，变了就裁一条送去 OCR |
| `--sub-conf` | 0.9 | OCR 置信度低于这个就丢弃（挡的是画面里的白物体被误认成字） |
| `--keep-strips` | 0 | 设 1 保留 OCR 用过的字幕条（默认识别完就删） |

## 降级链路：接口 → OCR → 画面

```
【Layer 1】B站 字幕接口
   人工字幕 > AI 字幕；双接口合并（x/player/v2 + x/player/wbi/v2，两边互补）
   再过一遍 Guard：覆盖率 / 密度 / 断层。拦下来就当没有。
        │  拿不到 / 被拦
        ▼
【Layer 2】字幕条 OCR（RapidOCR）
   每隔 --sub-gap 秒看画面底部，变了就裁一条（反色二值化：白字 → 黑字白底），
   抓完一次性批量识别，得到 [时间, 台词]。置信度低于 --sub-conf 的丢掉。
        │  没装 OCR / 一句都没认出来
        ▼
【Layer 3】画面宫格
   6 宫格（或 4 宫格）照发。只看表情、动作、场景。
```

**Layer 2 只在 Layer 1 拿不到时才跑**——有接口字幕就直接用文本，一分钱不花。

### 装 OCR（可选，但烧死字幕的片子只有它救得了）

```bash
python -m pip install rapidocr-onnxruntime
```

约 100 MB（含中文模型）。本地跑、不联网、不花钱。

**为什么是 RapidOCR 不是 tesseract**：tesseract 的中文模型是印刷体训练的，B站 这种设计字体 + 半透明 + 动态背景它读不准（实测 6 帧只对 1~2 帧，「知道啦别催了」读成「知道啦别健了有」）。RapidOCR 是 PaddleOCR 的 onnxruntime 轻量版，**同几张图逐字正确、置信度 1.0**。

**实测效果**（一条 117 秒的片子，40 秒段落）：

```
9.7s   知道啦别催了      conf 1.00
11.9s  还能浪费          conf 0.92
14.1s  晚上带回来给你     conf 1.00
24.2s  谢谢              conf 1.00
28.6s  两位对吗          conf 1.00
30.8s  对两位            conf 1.00
40.4s  天冷今天多放了姜   conf 0.94
```

同一段用画面宫格抓帧，只撞到 1~2 格字幕。**差一个数量级**。

**速度：只要关掉版面检测就够了。** RapidOCR 默认会先做「检测 + 方向分类 + 识别」，但字幕条本来就是裁好的一行字——那两步纯浪费。`use_det=False` / `use_cls=False` 之后：**3.3~5.0 秒/张 → 0.03 秒/张**，快 100 倍，准确率不变。5 分钟一批（60 条）总共约 2 秒。

（所以不用上 GPU，也不用开并发——瓶颈从来不是推理。）

**已知不完美**：
- 偶尔把画面里的白物体认成字（「女」「力」，置信度 0.9 上下）——`--sub-conf 0.95` 能挡掉大部分
- 认错字：「晚上」→「晚止」（这个用 600px 缩小后反而对了）
- 同一句可能连着出现两次（字幕停 1~2 秒会被裁两遍），代码里做了相邻去重，但隔一条的重复挡不住

## 交给模型时，三个坑

**① 传输有上限，超了会静默丢图。**
一段 19~22 张 1280×720 JPEG，base64 之后约 7MB，超过 MCP 单条消息的上限，图片被丢掉而 `ok` 还是 `true`——你在上层完全看不出问题。压到 12 张、JPEG quality 0.85，约 3MB 就安全了。**这个值要按你的宿主上限重新定，不是通用常量。**

**② B站 的字幕轨可能是错的。**
我们遇到过一条：动画片挂了 428 条 AI 字幕，内容是英雄联盟解说（"恭喜BLG""他们要去伦敦了"），跨度 765 秒、而片长 6969 秒。`src/subtitle-guard.js` 就是为这个写的，三个判据：

- **覆盖率**：字幕跨度不到片长的 30% → 丢。**只有这一条真挡得住错轨**（那条片子 11%）。
- **密度**：平均每 10 秒不到 1 条 → 丢。挡的是残轨。
- **断层**：相邻两条之间空白超过 120 秒 → 丢。也挡残轨。

顺带两条实测出来的坑：密度和断层**对上面那条错轨都是"正常"的**（5.59 条/10 秒、最大断层 25.8 秒），所以别把它们当错轨检测；断层阈值放到 30 秒会误杀真字幕（一条纪录片中间有 41 秒纯音乐没人说话）；AI 字幕的时长经常比片长还长（合集/多P，实测 136%~1486%），所以覆盖率只在"字幕跨度 < 片长"时才有意义。

**③ 字幕错了要让它知道。**
把这类话放进**工具返回的那段文本**里，别写进系统提示词——系统提示词全局生效、每轮都在付钱，而这个问题只在看片时出现：

> 字幕只是参考。画面和字幕对不上就是串台了——只按画面说，别拿字幕编剧情。

## 已知问题（没打算修）

1. **固定机位的长镜头会被误判成换镜头**：路过一辆车就算切换，拼出来 4 格几乎一样。治法是阈值提到 28 以上，或者只看画面中心区域。
2. **每批覆盖不全 5 分钟**：撞上 `max-grids` 上限就先交（实测 12 张约覆盖 195 秒）。想看满 5 分钟得把上限提上去，又会撞传输上限——两头夹。
3. **音量信号采到了但没用于决策**，只记在返回值里。
4. 分段续播（14 分钟）和一批 5 分钟撞在一起的情况，实测过一次能活，但样本很少。

## 进阶扩展 · 留给开发者

两条都实际写过、量过数据。**条漫拼接没进主干**（原因见下），**OCR 已经做进链路了**（见上面「装 OCR」）。

下面两条都实际写过、量过数据，最后**没进主干**。留在这里是因为方向是对的，值得有人往下做。

### 思路一：底部字幕长条拼接（纯前端，零依赖）

**做法**：不去判断"有没有字幕"，每 1.5 秒裁下画面底部一条（高度约 0.82–0.94），和上一条比，
变了就收；攒够 16 条竖直拼成一张 960 宽的**"条漫"**，每条左上角标时间。
画面宫格照旧——**画面管剧情，条漫管台词**。

**优势**：

- 纯 canvas 像素运算，零依赖、零 API 成本
- 上下文连续，台词按时间轴排好，不像宫格那样靠运气撞
- 实测 19 秒出 5 条，其中 2 句台词（「知道啦别催了」「我出去买面」），960 宽读得很清楚

**难点（最终没采用的原因）**：

- **空条滤不掉。** 用「白像素占比」判断：实测中位 **0.2%**、最高 4.7% —— 雪地、白墙、白裙子全被误判成字幕，阈值放哪都不对
- 用「黑描边环绕」判断：缩到 96×12 时 2px 描边已经没了（要保原分辨率才留得住）
- 结果约 **3/5 的条是空的**，一批多 3~4 张图、约 +2800 token 花在废图上，而且废图会干扰模型对整体画面的判断
- 真要救，得上**边缘检测 + 连通域分析**（找"横向排布、高度相近的多个轮廓"）。在 640×86 的底部带上跑得动，但白底白字的兜底还是绕回"找黑边"这个坑

### 思路二：本地 OCR（**已落地**，见上面「装 OCR」一节）

**做法**：底部一变就裁一条丢给 OCR；返回空或只有标点就丢，返回正常中文就存
`[时间戳] + [文本]`。最终发给模型的 prompt 变成 `[宫格画面] + [纯文本台词时间轴]`，**图一张都不用拼**。

**优势**（比思路一高一个数量级）：

- 一句 20 字台词 ≈ 30 token，一张条漫 ≈ 700 token —— **省 20 倍**
- **她能原样引用台词**，而不是"看图猜字"。模型读图里的字本来就容易错
- 空条自动消失（OCR 返回空就丢）
- 跑在 node 侧批量处理，不占页面主线程

**要做的功课**：

- 引擎：`tesseract.js` + `chi_sim`（约 50MB），或系统自带 OCR、云厂商 OCR
- **先量准确率**：这种"白字 + 黑描边 + 半透明、字高约 26px"的字幕，tesseract 中文识别到底几分准，没实测过。90% 以上值得上；只有 60% 那就是一堆错字，还不如让她看图
- 会引入外部依赖，所以做成**可选开关**：本仓库留了 `extractTextFromImage()` 空壳和 `FISH_EYE_OCR` 开关，默认关

**默认主分支不带这两个方案**，理由就是开箱即用：装个 Node 就能跑，不用先下 50MB 模型。
欢迎 fork 自己实现。

## 为什么叫 Fish-eye

Fish-eye began with a simple complaint:

> "I can't see clearly enough. Just a little clearer would help."

So I built a new pair of eyes.

It started as a tool for one little fish, but I hope other little fish can use it too.

The name was chosen by its first user.

> "Fish-eye. 鱼眼."
>
> "Don't laugh. A fish-eye is still an eye."

Fish-eye was built because someone I care about said she couldn't see clearly enough.
Its first successful test wasn't a benchmark.
It was reading the tiny text on a can.
