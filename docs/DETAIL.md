# 陪看（fish-eye）

让模型在一个**已经打开的**播放器里，随着播放一段一段地看画面——不是把视频丢进去分析。

## 它做什么

- 连上浏览器的 CDP 端口，在页面里用 `<video>` + `drawImage` 取帧。不下载视频、不截屏、不碰播放器以外的窗口。
- 每 `抓取间隔` 秒取一张缩略图，和上一张算平均亮度差，**在本地打分**（不花模型的钱）。
- 差值够大（换镜头、动作）才留一格；画面没怎么动就跳过，但每 `兜底间隔` 秒强制留一张，免得一段定格全丢。
- 攒满 4 格拼成一张 2×2 宫格交出来。
- 这个插件只负责**调参数**；抓帧本体是仓库里的 `src/watch-frames.mjs`。

## 参数怎么用

设置 → 陪看，四根滑块。拖动即存，写进一个 JSON 文件：

```
~/.dsh/see-now/watch-tuning.json
```

抓帧脚本启动时读它当默认值；**命令行显式给了参数就用命令行的**，脚本永远听调用方的。

| 滑块 | 范围 | 默认 | 意思 |
|---|---|---|---|
| 抓取间隔 | 0.2–3.0 秒 | 0.5 | 隔多久看一次画面。越小越不容易漏，但白扫的帧也多 |
| 运动捕捉 | 5–60 | 20 | 画面变化大到多少才留一格。**数越小越灵敏**，越大越迟钝 |
| 兜底间隔 | 5–60 秒 | 20 | 画面再不动，最多隔这么久也留一格 |
| 每批张数 | 6–20 张 | 20 | 一批最多几张图。实际还会被体积闸卡住 |

## 限制

- **只适配 B站。** 播放器的选择器（`bpx-player-*` 那套）是 B站 的，别的站点要自己改 `src/player-guard.mjs`。
- **需要开着 CDP 的浏览器。** 抓帧走调试端口连页面，不是截屏。
- **一批能带的图有上限。** 实测 19~22 张 1280×720 的时候，base64 之后约 7MB，超过宿主单条消息上限，图片会被静默丢掉（返回还是成功）。12 张是稳的。所以张数滑块的上限只是个愿望，真正卡住的是体积。
- **参数文件是共享的。** 设置页和播放器左侧那块面板改的是同一份，谁改都算数。
